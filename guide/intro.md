# Every design system is a set of answers

Open DS treats a design system as a fixed set of questions, answered on purpose. A **scheme** is one full set of answers. Each answer says why, and which earlier answers it follows from. Tokens, components, usage rules and voice follow from the answers.

You do not start by answering questions. You **pick a ready-made scheme**, then connect your AI and deploy it, or use the package yourself.

| You want to         | Read                                                   |
| ------------------- | ------------------------------------------------------ |
| Understand the idea | [Product: the vision](product/vision.md)               |
| See why it matters  | [Business: why it matters](business/why-it-matters.md) |
| See the questions   | [The grammar](../schemes/grammar.json), or the site's Questions page |
| Pick a scheme       | [The schemes](../schemes/), or the site's Schemes page |
| Deploy one          | [CLI](cli.md) or [MCP](mcp.md)                         |
| Let an agent use it | [For agents](agents/index.md)                          |

Every scheme ships as a full design system: Style Dictionary tokens (light and dark), components on shadcn and Radix, Storybook, these docs, `AGENTS.md`, an agent skill, and an MCP server.
