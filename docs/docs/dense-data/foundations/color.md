## The five answers

| Question | Answer | Why |
| --- | --- | --- |
| Which color roles does it need? | Surface, text, action and status | Surface, text, action and status cover an operations tool. |
| How many emphasis levels do actions need? | Three | One primary per view; the rest step back. |
| How is the palette defined? | Neutrals and one brand ramp | One product, one brand ramp on cool neutrals. |
| How saturated is the palette? | Muted | Muted color keeps attention on the data. |
| Where does color carry meaning first? | Status in tables | Color earns its place by marking late and failed records. |

## When to use what

| Situation | Use | Not | Why |
| --- | --- | --- | --- |
| A selected row or item | color.surface.selected | color.action.primary as a fill | A light tint shows selection without hiding the data. |
| An error message | color.status.danger with an icon | color.status.warning | Red always means fix this, and the icon says it without color. |
| A link | color.text.link | color.action.primary | Links and buttons look different, so people know which one navigates. |
| A status | Badge with a subtle fill, an icon and a word | A full-strength fill | Subtle fills let many statuses share one table. |
| The action that completes the task | Button primary, one per view | Two primaries side by side | One primary makes the committing action obvious. |
| An alternative or cancel | Button secondary | Button ghost | A ghost button has no edge, so next to a filled primary it reads as plain text and cancel gets lost. Secondary keeps a visible border, so people find it at once. |
| Delete or remove | Button secondary, then confirm in a dialog with Button danger | Button primary as the first step | Deleting is rare and costly; a confirm step catches mistakes. |

## Status urgency

Status colors go up in urgency: info, then warning, then danger. Pick the level that matches the real risk. Never go up a level to get attention. Success sits outside the order.

`color.status.info.@` → `color.status.warning.@` → `color.status.danger.@`
